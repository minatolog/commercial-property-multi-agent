# 面试短板补齐计划（2026-11）

- 写于：2026-11-21，对话模式中的 Claude；用户确认这 6 项为当前紧急、必须具备的能力。
- 背景：项目长期目标是交付地产公司，**当前首要目标是成为 AI 应用开发岗的面试作品**。已实现的能力全部保留，作为加分项。
- 本文件只负责排期与验收口径；契约、范围以 [当前基线](../architecture/CURRENT_BASELINE.md) 为准。每项开工时再写独立 Prompt。

## 1. 六项短板与对应任务

| 短板 | 面试会问什么 | 任务 | 完成的标志 |
|---|---|---|---|
| Agent 与 Workflow 的区别 | 你的多 Agent 智能体现在哪？什么时候用规则、什么时候让模型规划？ | **034 LLM Supervisor 规划器** | rule / llm / hybrid 三种规划可切换；改写问法评测集上有三者对照数据 |
| RAG 工程化 | 怎么切分？为什么这样切？召回怎么评测？ | **035 RAG 工程化** | 按条款语义切分 + BM25/向量混合召回 + rerank；recall@k、MRR、引用准确率三档对照 |
| MCP | 工具怎么标准化给外部 Agent 用？安全边界在哪？ | **033 MCP 网关**（Prompt 已有） | stdio MCP Server，`ToolExecutor` 仍是唯一入口；Flowise 或官方 Inspector 实测可调用 |
| 记忆 / 多轮对话 | 记忆怎么设计？换目标时权限怎么办？ | **036 会话记忆** | 会话内追问（"那 B-101 呢？"）可用；换目标重新走可信目标解析与授权；长会话摘要有上限 |
| 可观测性 / LLMOps | 线上怎么排查一次错误回答？成本怎么看？ | **037 可观测性 + 部署** | Langfuse 自托管接入，LangGraph 各节点、模型调用、工具调用可追踪，trace 与内部 run_id 互相可查 |
| 流式输出、部署 | 前端怎么实时展示 Agent 过程？怎么一键运行？ | **032 增补（SSE + 网页接模型）+ 037** | 网页可选真实模型并 SSE 流式展示各 Agent 进度；`docker compose up` 一键启动；GitHub Actions 跑全量测试 |

## 2. 执行顺序

0. **前置**：Task 031 返修（R1–R4）独立复查通过 → 分批提交 → 推送到 GitHub；同时加最简 CI（GitHub Actions 跑 unittest 与契约自检），后续每个任务都受它保护。
1. **034 LLM Supervisor**：最大短板，且后续评测、记忆、网页都依赖"规划来源"字段。
2. **035 RAG 工程化**：几乎每场面试必问；同时为后续能耗场景的电价、倍率、窃电条款检索打基础。
3. **033 MCP 网关**：沿用已有 Prompt；它同时是将来对接真实地产系统的接入层。
4. **036 会话记忆**：依赖 034 的规划输出与 Z1 可信目标解析。
5. **032 网页**：在原 Prompt 基础上增补"网页接入模型 + SSE 流式进度 + 规划来源展示"，到时写增补说明。
6. **037 可观测性 + Docker**：Langfuse 依赖 Docker，两者一起做；CI 已在第 0 步完成。

每个任务：一次只做一个 → 实施者自检 → 另一个模型独立复查 → 提交 → 再开始下一个。

## 3. 与能耗稽查场景的关系

用户实习经历中的水电费账单混乱、收缴不齐、窃电问题，计划作为项目主场景（另立 ADR，届时把"能耗"从暂停范围中移出）。**先补齐上述基础能力，再接入能耗场景**，理由：

- 上面 6 项都是与场景无关的基础设施，先做完，能耗场景接入时直接复用；
- 能耗场景接入本身就能证明 Registry / 规划器 / MCP 的可插拔性，是面试时的第二个故事；
- 034 的改写问法评测集、035 的条款检索评测，届时直接扩展到能耗题目即可。
