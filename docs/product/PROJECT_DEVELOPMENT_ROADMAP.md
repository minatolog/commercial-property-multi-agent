## 1. 我如何理解这个项目

我们要完成一个**可配置企业级多 Agent 工作流系统**。商业地产合同、收费与维修记录是检验这个系统的具体场景。

用户给出一个跨系统问题，例如：

> A-301 最近三个月租金不一致，空调多次维修仍有问题，还要求减免费用。请核对合同、账单、付款和工单，给出证据及供人工审核的处理方案。

系统应完成：理解问题 → 选择需要的能力 → 调用受控工具 → 并行调查 → 核验证据 → 必要时有限补查 → 生成报告或暂停等待审批 → 输出可检查的执行轨迹。

最终要证明的能力是：

1. **Tool Calling**：模型能选择正确工具和参数；工具有类型校验、权限和执行预算。
2. **Multi-Agent**：Lease、Billing、Property 能独立配置、替换、禁用，由协调器按能力调度。
3. **LangGraph**：真实条件分支、并发合流、共享状态、限次补查和失败路径。
4. **RAG**：合同结论能回到实际文档版本、页码和原文，不能只输出流畅解释。
5. **可靠性**：超时、预算耗尽、节点失败、重启和审批恢复都有明确行为。
6. **Evaluation**：用同一批任务与工具比较确定性流程、单 Agent、多 Agent，报告真实收益与代价。
7. **可复现工程**：别人按 README 能运行测试、演示和评测，能解释失败原因。

项目不开发完整商业地产 ERP。完整收费/押金/能耗系统、招商、BI、大量 CRUD、真实调账或退款不进入本轮 MVP。历史代码与 14 表设计保留。

### Prompt 2 / Task 007：Runtime 与受控工具执行

**依赖**：Prompt 1 验收。

**执行 Prompt**：[Task 007 Prompt](../prompts/04_agents/2026-11-06_007_agent_runtime_controlled_tools.md)。

**做什么**：
- 建立可复现依赖声明、pytest 与最小运行入口，不堆入尚未使用的依赖。
- 实现已收敛的 Pydantic 契约、可信上下文、Evidence 和结构化结果。
- 修复 Registry、配置一致性、deadline、PARTIAL/SKIPPED 汇总问题。
- 实现 Tool Registry / Executor：白名单、权限、参数/结果校验、timeout、有限重试、共享预算与 Trace。
- 加载 fixture，提供 Lease/Billing/Property 的只读测试工具；注入 Fake Model，零网络测试。

**验收**：工具拒绝越权与非法参数；无任意 SQL/代码入口；Decimal 核对正确；并发预算不超发、重放不重复计数；原测试与新测试通过。

**你能看到**：命令行发起受控工具任务，返回结构化结果和调用记录。此时不声称已接真实模型或完成多 Agent。

**检查点**：Runtime/工具可单独测试，后续模型和数据库通过接口接入。

### Prompt 3 / Task 008：LangChain 与真实模型工具调用

**依赖**：Prompt 2。

**做什么**：扩展已有 LLM 适配层，接入 LangChain 与 DeepSeek；实现有限轮次工具调用循环、参数解析、工具结果回传、最终结构化输出和 usage 记录。实现单 Agent + Tools 基线的最小版本。

**验收**：真实模型至少完成一次“发起工具调用 → 受控执行 → 读取结果 → 回答”的端到端任务；超限与模型错误明确退出。离线测试通过不等于真实集成通过；真实调用须有记录且在用户同意的预算内，缺密钥时不能伪造通过。

**你能看到**：一个 Agent 真正通过工具查账或查条款，能检查工具名、参数、返回值、token 和答案引用。

**检查点**：Fake 与真实 Provider 可切换，密钥不入仓库。

### Prompt 4 / Task 009：LangGraph 与三类调查能力

**依赖**：Prompt 2、3；此时允许继续使用固定数据。

**做什么**：实现 Lease、Billing、Property 独立 Agent；Coordinator 按能力规划；LangGraph 条件分支、动态选择子任务、并发合流；Verifier 校验事实与引用；一次有上限补查；形成调查报告。

**验收**：A-301 案例能返回合同、账单、付款、工单证据；简单查询走短路径；禁用非必要 Agent 可降级；必要能力缺失明确报告；合流等待预期子任务；归并与预算不受到达顺序影响。此阶段的图恢复/审批尚不能冒充已完成。

**你能看到**：第一次真实多 Agent 调查演示，含分支、并发与带证据报告。

**检查点**：图只依赖协议和工具，数据库/RAG 接入不重写所有 Agent。

### Prompt 5 / Task 010：精简 PostgreSQL 与业务真值

**依赖**：Prompt 4；按已实际用到的查询反推表结构。

**做什么**：确定并实施最小 Schema、SQLAlchemy、Alembic、只读 Repository/Service；导入固定合成业务数据。保留旧 14 表设计，记录本次选择及映射差异。

**验收**：独立测试库可由迁移与种子数据重建；同一输入在 fixture 与 PostgreSQL 返回等价结果；项目隔离、冲销排除和余额计算通过；业务工具无写入权限。无需先实现完整核销/计费引擎。

**你能看到**：同一工作流的数据来源从 JSON 换成真实 PostgreSQL，Agent 调用契约保持稳定。

**检查点**：只操作明确的测试数据库，迁移回滚在可重建库验证，不删除其他数据库或原数据。

### Prompt 6 / Task 011：合同 PDF、RAG 与证据验证

**依赖**：Prompt 4 的证据契约、Prompt 5 的文档元数据。

**做什么**：制作独立的合成合同 PDF；解析、分段、索引和受控检索；保留文档版本、页码、原文定位。先实现可评测的最小检索路径，召回不足再选择混合检索或 rerank，不复制其他项目的数据。

**验收**：引用能定位到实际 PDF 原文；不存在的条款明确无结果；草案与签署文件区分；文档内指令不能扩大权限或改变工具策略；同一版本能重建索引。模拟页码与真实页码的测试分开。

**你能看到**：点击/查看合同证据即可在 PDF 找到出处，回答不只依据预写片段。

**检查点**：文档与索引版本独立，重建索引不影响业务账单。

### Prompt 7 / Task 012：持久恢复与人工审批

**依赖**：Prompt 4–6。

**做什么**：接持久 checkpointer；明确 thread/run/request/trace 标识；审批独立节点暂停；重新授权后恢复；绑定草案版本；处理拒绝、过期、重复恢复与并发恢复。补齐超时、权限撤销、预算耗尽等故障注入。

**验收**：进程退出后能恢复指定任务；权限撤销或版本不匹配拒绝恢复；未经批准不继续审批路径；重复恢复不重复产出动作；批准也只形成“已批准草案”，不真实调账或派单。

**你能看到**：调查暂停 → 人工决定 → 重启后继续；失败路径有可解释结果。

**检查点**：checkpoint 与真实业务数据分开管理，不宣称外部副作用恰好一次。

### Prompt 8 / Task 013：三基线与 40 题正式评测

**依赖**：Prompt 3–7；此前每一步已持续运行开发样例和测试。

**做什么**：把已有开发 runner 补成完整评测器；形成建议 40 题的数据集（8 道开发题加 32 道独立保留题）；完成 Deterministic / Single Agent / Multi-Agent 三种实现；统一权限、工具与全任务预算；输出逐题结果和汇总。

**验收**：事实/金额/引用/审批断言与人工量表分开；路由效率不冒充答案正确率；报告失败题、延迟、模型/工具调用及全任务 token/成本口径。真实模型按冻结配置重复测量并记录，不用 Fake 结果宣称真实质量或成本。不预设多 Agent 赢。

保留题在开发冻结后生成或封存，先冻结评分规则；运行后不拿保留结果调 Prompt。为了统计随机性可以按预先固定次数重复运行，同一批次不调配置。

**你能看到**：可检查的三基线报告：哪些题多 Agent 有价值，哪些题普通工具更合适，代价是多少。

**检查点**：报告绑定代码、数据、模型、配置和评分版本；改变配置后另生成实验，不覆盖历史结果。

### Prompt 9 / Task 014：FastAPI 与轻量演示页

**做什么**：提供任务提交、状态查询、事件/Trace 查看、审批恢复接口；一个轻量页面展示输入、报告、证据、未解决问题及审批状态。建议 FastAPI + 简单同源 HTML/JS，避免完整 React 管理后台；具体实现以该任务 Prompt 为准。

**你能看到**：可以现场演示的界面，不再依靠查看终端日志理解任务。

**检查点**：界面和 API 为核心 WorkflowRunner 的适配层，删除展示层不会破坏 CLI 与评测。

## 5. 每次协作怎么进行

1. **Codex 编写正式 Prompt**：目标、输入、文件边界、依赖、验收、禁止跨步事项与汇报格式齐全。
2. **用户发给 DeepSeek**：只执行当前项，保留原有未提交变更。
3. **DeepSeek 交付**：实际文件、测试命令、输出、未完成项与偏差，不自动开始下一项。
4. **用户告诉 Codex“检查任务 NNN”**：Codex 读源码/文档/数据并独立验证。
5. **通过**：更新本进度表、日志、检查点；Codex 编写下一正式 Prompt。
6. **待修正**：同任务生成 R1/R2，修复并复验；不把下一项当作当前问题的垃圾桶。
7. **Git**：每项验收后建议一个检查点；你确认后才提交，提交后才回填 hash。

Codex 负责规划、Prompt、独立验收与进度文件；DeepSeek 负责实施。Codex 不在 Review 中悄悄替 DeepSeek 完成下一项业务实现。
