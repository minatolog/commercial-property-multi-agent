### 4.1 精确盘点现状（不凭记忆）

1. 用脚本提取 §8.2 / §8.3 / §8.4 的行数与全部索引名，而不是依赖文档文字里"17 / 21 / 2"的说法。

3. 逐条比对"约束自动创建的索引"与手工索引清单，定位重复。

### 4.2 逐项技术复核，发现 12 项缺陷

**其中 2 项为严重缺陷，直接改变结论**：

- **D1（严重）**：`lease_units.occupied_to` 允许 `NULL` 且语义写成"至租约结束"，而排他约束用 `COALESCE(occupied_to,'infinity')`。后果：`NULL` 被解释为**无限期占用**，该商铺被永久锁死，后续任何租约都无法录入。约束不但没防冲突，反而阻塞业务。
- **D4（高）**：`blocks_occupancy` 只有列默认值 `false`，没有初始化触发器。若先建 `active` 租约、后插占用行，该行 `blocks_occupancy=false` → **排他约束完全不生效**，静默失效。

D1 与 D4 组合意味着：**v1 的排他约束在最需要它的场景下既不生效、又可能锁死商铺**。这不是文档表述问题，是设计错误。

其余：D2 表达式索引改用生成列；D3 占用时间与租期无约束；D5 核销缺冲销字段；D6 枚举含 `deposit`；D7 计费面积可空导致隐式回退；D8 `documents` 项目一致性；D9 计数错误；D10 冗余索引；D11 并发方案缺失；D12 "不可变"表述矛盾。

## 7. 遇到的问题及解决方法

| 问题 | 原因 | 解决 |
|---|---|---|
| 排他约束内能否直接写 `daterange(...)` 表达式存在不确定性 | 表达式索引在约束场景的行为不如普通列明确，且 `COALESCE` + `'infinity'` 语义易被误读 | 改为 `GENERATED ALWAYS AS (...) STORED` 生成列，约束只引用普通列。既消除不确定性，也让 `\d` 输出与报错信息更可读 |
| 用 `NULL` 表示"至租约结束"会锁死商铺 | 约束只能看到列值，`NULL → COALESCE('infinity')` | 全部区间端点改 `NOT NULL`，由触发器从来源字段物化；并新增 §2.9 作为通用规则 |
| `blocks_occupancy` 可能在插入时取默认值导致约束失效 | 只有 `AFTER` 传播触发器，没有 `BEFORE` 初始化触发器 | 两个触发器都加，并在 §15.2.3 用场景 3 专门验证 |
| §8.2 计数与实际不符 | v1 把 `units` 的两条约束写在同一表格行 | 重列为 15 行、每行一条；在表下显式记录"v1 实为 18 条"的纠错说明 |
| 视图漏掉冲销过滤 | v1 无 `reversed_at` 字段，视图无需过滤 | 新增字段后必须同步改视图，已在 §10.3 补 `AND pa.reversed_at IS NULL` |
| PowerShell 正则中 `?` 被当作量词导致校验脚本报错 | 正则转义问题 | 改用显式字符组与两次 `-match` 校验 |
