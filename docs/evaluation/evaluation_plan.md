## 2. 三基线与公平比较

| 基线 | 形态 | 限制 |
|---|---|---|
| A_deterministic | 固定规则与受控工具 | 不调用 LLM |
| B_single_agent | 单 Agent + 同组工具/RAG | 不拆多 Agent 扇出 |
| C_multi_agent | 规则规划 + 领域 Agent + Verifier + 审批 | 能力受控、按需并发、有限补查；领域 Agent 可用 LLM 引擎 |

事实、金额、证据、权限、审批使用共同质量判据；路由作为效率指标，不能因 B 没有多 Agent 路由就判答案错误。比较时冻结工具/权限/数据及全任务预算；B/C 模型条件需说明。A 的 token=0 不可解读为模型调用免费。

## 3. 评分和证据

- 当前事实比较按同名字段，金额以 Decimal 到分；不可用“文本出现过这个数字”代替字段绑定。
- 工具事实、字段级资金结论、辅助金额接地分别计分；unverified 转人工并单列，不当通过。
- 引用区分存在与支持结论；BM25/机械规则不代表完整语义理解。
- 预期拒绝/失败须按 expected_outcome 对称评分；人工 rubric、契约外不可判定项不混入自动分母。
- 历史 scoring-v1/v2/v3/v3.1 报告保留。规则变更另升版本、另建报告，不用新规则重写真实历史测量，也不跨评分版本比较通过率。

现有离线 scoring-v3.3：A 20/30、B 21/30、C 23/30；它们只证明当前离线路径在该数据/评分下的表现。真实 dev 与单题只证明有界运行，不能支持正式 B/C 质量优劣结论。最新独立证据见 [Task 025](../reviews/2026-11-07_q1_q3_acceptance_review.md)。

## 4. 数据、变体与场景协议

fixture 只读；overlay 在副本上应用，不原地改基础数据。预期答案、断言和人工标准只供评测器读取，不能注入被测 Agent 或工具。权限从可信主体构造，不由题目文本自行授权。

C06 超时主路径/恢复 probe、C08 六个审批场景的原始协议保留在 [历史规格 §2、§5](evaluation_plan_legacy_2026-11-09.md)。场景必须用 scenario_id 连接，不按数组位置猜测；失败取证路径不强迫返回不存在的证据。**本轮未新增或独立证明 runner 已完整执行旧协议的每个场景**；对应可靠性还需结合测试/逐场景产物验收，不可用“8 题都有结果”替代全部分支覆盖。

## 5. 正式实验步骤

1. 先闭合当前代码缺陷和模型配置策略；固定候选代码、数据、评分、Prompt、模型参数、预算、检索配置。
2. 事前固定重复次数（可采用 N=3，最终以实验方案为准），同批次不调参；保存全部运行，不挑最好的一次。
3. 对 B/C 跑同一批题，并保留 A 的确定性参照。记录实际 provider/model、配置摘要、代码/数据校验和、模型物理请求、工具逻辑调用及尝试、tokens、失败/拒绝/超限和墙钟延迟。
4. 完成人工量表与无法机械判断的资金/引用题；预先明确通过标准和评分人，报告人工与自动结果各自的分母。
5. 汇总全部重复的质量、延迟、tokens 与失败分布；成本金额需注明冻结价格来源和币种，未换算时标 n/a，不填 0。

旧 heldout 已被开发查看和反复运行，不能无证据称为未曝光盲测。现有结果标明探索/回归用途；需要独立泛化结论时另建未用于调试的冻结测试集，保留旧版本。此原则不授权删除或改写现有题目。

## 6. 运行与验收

在 backend 目录运行离线评测：

```powershell
python -m app.cli evaluate --split heldout
```

真实实验使用 --model-provider deepseek，在已有有效凭据、明确预算和新报告位置的条件下按冻结方案执行；本次文档任务不调用真实模型。scripted 只验证装配，缺密钥明确失败，不降级冒充真实测量。

完成标准：质量/安全/恢复/可插拔证据可复查，逐题与重复结果齐全，人工队列实际评分，失败和限制如实披露。PostgreSQL 实机等其他 MVP 验收要求不因评测报告生成而自动关闭。
