## 2. 尚未闭合的问题

本报告使用 Q1–Q3，仅作为本轮发现编号。

### Q1 [P1] token 预算已经耗尽，仍会发送后续模型请求

- **位置**：`backend/app/runtime/tool_loop.py:89`、`:111`、`:126`、`:165`；`backend/app/runtime/budget.py:59`、`:158`。
- **关联**：N1。
- **原因**：发送前只预留模型调用次数；reserve_model_call 没有检查 token 已用量。首次响应超出 token 预算后虽然正确记录超额并返回 budget_exhausted，图补查/再次调用仍能预留下一次模型请求，直到第二次响应返回才再次发现 token 已耗尽。
- **本次复现**：max_model_calls=10、max_total_tokens=5；Fake 每次响应消耗 10 tokens。首次返回后预算已明确耗尽，图仍执行一次补查。实际物理调用 **2 次**，used_total_tokens=20、exceeded_tokens=15、revision=1。
- **边界**：一次请求的实际用量要等响应后才知道，首次超出预算与“明知已经耗尽后仍继续发请求”应分开处理。本项复现的是后者。
- **影响**：已有消耗记账更准确，但 token 上限仍不能阻止后续费用。不能把“如实记录超额”当作“预算能阻止后续请求”。
- **修复验收**：模型发送前，以并发安全方式检查并预留本次允许的预算；至少保证 token 已耗尽/超额时拒绝新物理请求，包括图补查、Agent 重试、其他共享预算的子任务。保留真实已发生的用量与超额记录。覆盖 max_total_tokens=0、首次超额后的顺序调用、共享预算并发和图补查。

### Q2 [P1] 单 Agent / B 基线没有接入可信任务范围，仍能取错目标租约

- **位置**：`backend/app/agents/single/agent.py:100`–`:105`、`:130`；`backend/app/evaluation/baselines.py:381`、`:409`–`:419`。
- **关联**：N2/N3。领域 LLMToolAgent 的 TaskScope 修复没有覆盖 SingleToolAgent。
- **原因**：B 基线已经把解析后的 lease_id 放入 request.payload，但 SingleToolAgent 没有从该字段构造任务范围，也没有向 run_tool_loop 传 prepare_arguments；事实提取前没有校验结果实体。模型消息仍只有 question。
- **本次复现**：在内存 fixture 中给可信主体两个项目权限；用例目标为 A-301，Fake 调用 B-101 的 billing.statement.read，再回答“A301 应收 0.00、已收 0.00、未收 0.00，已经结清”。B 基线实际返回 status=ok、三个金额 facts 全为 0.00、errors=[]。这些是 B-101 的真实工具数据，却被拿来回答 A-301。
- **边界**：没有绕过主体的项目权限；错误在于有权访问的另一实体被当作本次业务目标。评测的正确期望金额可以使该题失分，但运行链路本身依旧接受错误归属。
- **影响**：C 的领域 Agent 受可信目标约束，B 的 SingleToolAgent 没有同等约束；单 Agent 入口及对照实验的执行规则不一致。文档检索也应统一接入这一可信范围，而非让模型自行声明 lease_id/document_ids。
- **修复验收**：SingleToolAgent、B 基线与领域 Agent 共用任务范围构造、工具参数约束、输出实体核验；明确纯说明任务与有目标业务查询的差别。测试 B 的错误租约调用、其他租约文档、模型省略范围以及合法纠正；不能只扩展领域 Agent 测试。

### Q3 [P1] 金额集合匹配仍放过结论写反，答案错误却得到满分

- **位置**：`backend/app/agents/base/narrative.py:129`–`:174`；`backend/app/evaluation/scoring.py:325`–`:329`。
- **关联**：N6。
- **原因**：校验只检查金额是否出现在可信金额集合，以及集合中的金额是否都被提及；没有绑定“应收/已收/未收”等字段与对应值。工具输出的任意金额被加入集合后，其他明细中的 0.00 也可能被用于错误的未收结论。
- **反例 A：三个金额全部写反**：
  - 工具 facts：应收 52596.00、已收 34560.00、未收 18036.00。
  - 用户答案：“应收 34560.00 元，已收 18036.00 元，未收 52596.00 元。”
  - 实际 answer_check=consistent，detail 声称“答案金额与工具事实一致”，评测 **passed=true，4/4**，无错误警告。
- **反例 B：写一个正确金额，搭配错误结清结论**：
  - 用户答案：“应收 52596.00 元，未收 0.00 元，已经全部结清。”
  - 0.00 来自账单明细的可信集合；校验只标 incomplete，ok=True，答案断言转人工；整体仍 passed=true、事实断言 3/3。
- **影响**：scoring-v3.1 能抓住一部分编造数值，却仍不能证明资金结论正确。把所有数字都写出来即可获得“答案一致”，与是否答对这些金额的含义无关。
- **修复验收**：将资金结论绑定为结构化字段，并保证用户可见金额由可信字段渲染，或对明确的字段声明做对应校验。金额存在性检查可作为辅助，不能单独输出“答案准确”的结论。必需的最终答案校验若尚未判定，应明确为未验证，与内部事实通过分开统计。增加以上两个反例，以及字段交换、错误结清、正确只答未收、合法明细说明等测试；评分逻辑改动继续升版并保留旧报告。
