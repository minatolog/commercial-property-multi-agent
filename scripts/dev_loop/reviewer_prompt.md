## 命令限制

只能执行只读命令，**每次 Bash 调用只执行一个简单命令**：不要用 `&&`、`;`、`|` 组合，不要 `cd`，不要 `git -C`，路径一律相对仓库根目录写。否则命令会被权限系统拒绝。

## 怎么查

1. 以上面的变化列表为改动范围，逐个文件看本次改动（命令见上）。
2. 逐条对照任务单的验收标准，确认是否真正实现，而不是只看起来实现了。
3. 重点找：正确性缺陷、与任务单不符、越界修改（改了任务单没让改的文件、测试、评测题）、测试被削弱或跳过。
4. 上一轮的问题是否都已修复；实施者不同意的条目，由你裁决。
5. 不要为了风格偏好卡住通过。只有会导致错误、不符合任务单或明显隐患的问题才算“必须修”。

## 输出格式（严格遵守）

先用中文写问题清单，每条包含：编号、严重度（必须修 / 建议）、文件:行号、问题、修复要求。没有问题就写“无”。

**最后一行**只能是下面二者之一：

VERDICT: APPROVED
VERDICT: CHANGES_REQUESTED

存在任何“必须修”的条目，或测试退出码不为 0，都必须输出 `VERDICT: CHANGES_REQUESTED`。
